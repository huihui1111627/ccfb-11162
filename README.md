# 华源集团合并报表系统（TypeScript 全栈）

面向多法人集团月底合并报表场景：各子公司报数 → 自动内部往来/交易核对与抵消 → 外币折算 →
少数股东权益/损益 → 合并底稿，带 React Web 端。

## 一、技术架构

```
workspace/
├── shared/          # 前后端共享领域模型（科目字典、类型、月份工具）
├── server/          # Express + 引擎（纯 TypeScript，无框架依赖的合并核心）
│   ├── src/
│   │   ├── seed/        # 虚构集团数据：15 主体/三层持股/三币种/12 个月/故意不一致的内部交易
│   │   ├── engine/      # 合并引擎 8 个模块（见下）
│   │   ├── manual/      # 独立手工合并底稿（不依赖引擎逻辑，从原始数据重算）
│   │   ├── store.ts     # JSON 原子持久化
│   │   ├── routes.ts    # REST API
│   │   └── server.ts
│   └── runtime/         # 运行期 state.json、手工核对报告（git 忽略 state）
└── web/             # React 18 + Vite，五个业务页面
```

- 金额口径：主体报送本位币、整数、利润表为年初至本月末 YTD 累计、资产负债表为时点数；合并层统一 CNY。
- 数据可复现：虚构数据由固定种子的伪随机生成器产生，每次完全一致，手工底稿才能逐月对得上。

## 二、八条业务规则与引擎模块映射

| # | 规则 | 实现位置 |
|---|------|----------|
| 1 | 合并范围按控制权判断，持股不过半但实质控制也纳入并写明依据 | `engine/ownership.ts`（持股图 DFS 算有效持股/控制链，`ScopeDecision.basis` 写依据） |
| 2 | 内部应收应付、内部销售采购两边金额对比，差额列原因 | `engine/reconciliation.ts`（双方折 CNY 后按较小者抵消，差额挂账 + 原因代码 TIMING/FX/OMISSION/AMOUNT） |
| 3 | 未实现内部利润按存货留存比例抵消 | `engine/urp.ts`（借营业成本/贷存货；逆流交易按 NCI 比例分摊） |
| 4 | 外币按期末汇率/平均汇率分项目折算，差额进折算差额 | `engine/translation.ts`（资产负债期末汇率、利润表平均汇率、投入资本历史汇率、CTA 轧差） |
| 5 | 少数股东权益和少数股东损益自动计算 | `engine/investments.ts`（有效持股连乘得 NCI%，含逆流 URP 冲减） |
| 6 | 年中收购/处置按时间折算并入 | `ownership.ts` 报告期判断 + 种子数据 A2/C2 4 月收购、D1 8 月处置 |
| 7 | 抵消分录可追溯来源单据，手工调整必须写理由 | 分录 `sourceRefs` 字段；`routes.ts` 后端强制理由≥4字、借贷平衡校验 |
| 8 | 合并底稿逐项显示个别数、抵消数、合并数 | `engine/worksheet.ts`（四栏底稿，派生合计行合并后重算） |

另有 `engine/profitCarry.ts`：把利润表侧抵消事项结转到留存收益，保证合并资产负债表配平。

## 三、虚构集团设定

- **15 家法人主体**：母公司 P + 13 家纳入合并子公司 + 1 家联营 F1（持股 40% 不控制，不纳入）。
- **三层持股**：P → 第一层 A1/A2/B1/C1 → 第二层 B2~D3 → 第三层 E1/D1。
- **实质控制案例**：A2 直接持股仅 45%，凭一致行动协议+董事会 5/7 纳入；D1 持股 40%，凭经营管理委托协议纳入。
- **三种币种**：CNY（境内主体）、USD（B1/B4/D2）、EUR（C1/D3）。
- **年中事件**：A2、C2 于 2026-04 收购并入（合并范围 12→14 家）；D1 于 2026-08 处置，9 月起出表（14→13 家）。
- **故意不一致**：10 组内部往来、10 组内部购销中多组预设偏差（在途/汇率/漏记/金额差异），8 月有 10 组核对差额。
- **商誉**：A2 收购形成商誉 4,340 元、C2 形成 1,040 元。

## 四、运行方式

```bash
npm install                      # 安装全部 workspace 依赖

# 开发模式（服务 4000 端口，Web 5173 端口自动代理 /api）
npm run dev

# 或分别启动
npm run dev:server
npm run dev:web

# 生产构建 + 启动（服务端同时托管 web/dist）
npm run build
npm start                        # http://localhost:4000

# 引擎测试（17 个用例，覆盖 8 条规则 + 全年 12 月配平）
npm test

# 独立手工底稿核对（2026-08，输出 runtime/manual-report.json）
npm run manual
```

## 五、手工底稿核对结论

选取 **2026-08**（含收购并入主体、处置前最后月、三币种、全部四类差异原因），
`server/src/manual/manualWorkbook.ts` 从原始种子数据出发，按准则独立重算 9 个步骤
（范围→折算→汇总→往来抵消→交易抵消→URP→长投/NCI→少数股东损益→结转），
与引擎结果 **27 个报表行逐项核对，差额全部为 0，完全一致**。

系统侧每月自动跑 5 项校验，全年 12 个月共 60 项全部通过：
抵消分录借贷平衡、合并资产负债表配平、各主体折算后配平、合并范围完整、利润表勾稽。

## 六、Web 端五个页面

1. **组织架构与合并范围**：三层持股树、有效持股、每家主体的纳入/不纳入判定依据
2. **报表采集**：任选主体/月份查看本位币两张报表与当月期末/平均汇率
3. **内部往来核对**：往来、购销、URP、原始单据四个页签，差额与原因、抵消分录号
4. **抵消分录**：按类型筛选、展开借贷明细、来源追溯；在线录入手工调整（理由必填、平衡校验）
5. **合并底稿**：四栏底稿、配平校验结果、手工底稿 9 步骤与逐行核对
